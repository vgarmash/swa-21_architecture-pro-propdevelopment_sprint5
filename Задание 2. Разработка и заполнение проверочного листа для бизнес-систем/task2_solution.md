# **Проверочный лист безопасности бизнес-систем PropDevelopment**

## **Обоснование выбора разделов проверочного листа**

На основе описания компании PropDevelopment и анализа архитектурной диаграммы C4 были выбраны следующие разделы проверочного листа:

1. **Управление доступом** – Ключевой раздел, так как в компании есть:
    - Множество систем аутентификации (`auth-service-1`, `Active Directory`, `accountant-service-1`)
    - Разные категории пользователей (клиенты, собственники, менеджеры, бухгалтеры)
    - Проблемы с доступом через API партнёров

2. **Безопасность данных** – Центральная проблема компании:
    - Нарушен контроль данных между системами
    - Данные передаются через CDC в хранилище
    - Множество баз данных с персональными и финансовыми данными

3. **Защита инфраструктуры** – Актуально из-за:
    - Гибридной инфраструктуры (приватное облако, ЦОД, облачный провайдер)
    - Наличия межсетевых экранов на диаграмме
    - Сетевых взаимодействий между доменами

4. **Управление инцидентами** – Важно для:
    - Реагирования на инциденты (упоминались утечки у конкурентов)
    - Отсутствия SIEM на диаграмме
    - Необходимости мониторинга сложной распределённой системы

5. **Специфические аспекты** – Включает:
    - Вопросы по мобильному приложению для собственников
    - Интеграции с внешними системами (госорганы, платёжные системы)
    - Физическую безопасность (собственный ЦОД)

## **Выводы для аудита безопасности на основе диаграммы C4:**

1. **Архитектура сложная и распределённая** – 11+ контейнеров, 8+ баз данных, множество интеграций.
2. **Множество точек входа** – 2 витрины, мобильное приложение, внешние API.
3. **Интеграции с внешними системами** требуют особого внимания:
    - Государственные органы (СМЭВ)
    - Платёжные системы
    - Поставщики ЖКХ
4. **Используются современные технологии** – Kafka, Keycloak, Spring Boot, что требует соответствующих мер безопасности.
5. **Нет централизованного мониторинга и управления доступом** – SIEM отсутствует, учётные записи разрознены.

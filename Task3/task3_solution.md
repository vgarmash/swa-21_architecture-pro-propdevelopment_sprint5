# **Требования к внешней интеграции для сервисов "Умный дом"**

Требования сформированы с учетом архитектуры PropDevelopment, существующих проблем безопасности и специфики сервисов "Умный дом".

## **1. Требования к безопасности**

### **1.1. Конфиденциальность данных**
| Требование | Описание | Обоснование |
|------------|----------|-------------|
| **Шифрование передачи** | Все данные передаются по TLS 1.3+ с использованием сильных шифров (AES-256-GCM) | Защита от перехвата трафика между системами |
| **Шифрование хранения** | Персональные данные (биометрия, номера автомобилей) шифруются на стороне партнёра | Соответствие 152-ФЗ о персональных данных |
| **Изоляция ключей** | API ключи и токены хранятся в HashiCorp Vault/AWS KMS, а не в конфигурационных файлах | Предотвращение компрометации при утечке кода |
| **Минимизация данных** | Передаются только необходимые данные (user_id, permissions, timestamp) | Принцип минимальных данных |

### **1.2. Целостность данных**
| Требование | Описание | Обоснование |
|------------|----------|-------------|
| **Цифровые подписи** | Все команды на изменение состояния (открыть/закрыть) подписываются | Защита от подделки команд |
| **Валидация входных данных** | Strict schema validation всех входящих запросов | Предотвращение инъекций и аномальных данных |
| **Контроль версий API** | Использование версионирования API (v1/, v2/) | Гарантия совместимости при обновлениях |

### **1.3. Доступность**
| Требование | Описание | Обоснование |
|------------|----------|-------------|
| **SLA партнёра** | Доступность API партнёра не менее 99.9% | Критичность сервисов безопасности |
| **Грейсфул деградация** | При недоступности партнёра система сохраняет базовую функциональность | Непрерывность работы |
| **Резервные механизмы** | Физические ключи/карты доступа как fallback | Гарантия доступа в ЧС |

### **1.4. Аудит и мониторинг**
| Требование | Описание | Обоснование |
|------------|----------|-------------|
| **Полное журналирование** | Все операции доступа фиксируются с timestamp, user_id, device_id | Расследование инцидентов |
| **Хранение логов** | Журналы хранятся не менее 1 года | Требования регуляторов и внутренние политики |
| **Алертинг** | Автоматические оповещения при подозрительной активности | Быстрое реагирование на инциденты |

## **2. Протоколы аутентификации и авторизации**

### **2.1. Аутентификация**

#### **Уровень 1: Система-система (PropDevelopment ↔ Партнёр)**
```
Протокол: Mutual TLS (mTLS)
Механизм:
1. Каждая сторона имеет собственный SSL-сертификат
2. Сертификаты выдаются внутренним CA PropDevelopment
3. Двусторонняя проверка сертификатов при каждом соединении
4. Срок жизни сертификатов: 90 дней

Альтернатива: API Key + HMAC
- API Key в заголовке X-API-Key
- HMAC подпись тела запроса с использованием секретного ключа
- Timestamp для предотвращения replay-атак
```

#### **Уровень 2: Пользовательские запросы**
```
Протокол: JWT (JSON Web Tokens)
Схема:
1. Пользователь аутентифицируется через auth-service-1 (Keycloak)
2. Выдается JWT token с claims:
   {
     "sub": "user_123",
     "aud": "smart-home-gateway",
     "exp": 1672531200,
     "permissions": ["smart-home:access:read", "smart-home:access:write"],
     "property_id": "complex_5"
   }
3. Access token живет 15 минут
4. Refresh token живет 7 дней (хранится в httpOnly cookie)
```

### **2.2. Авторизация**

#### **Модель RBAC (Role-Based Access Control)**
```yaml
Роли:
  tenant_owner:
    - smart-home:devices:read
    - smart-home:access:write
    - smart-home:events:read
    - smart-home:guests:manage
  
  tenant_family:
    - smart-home:devices:read
    - smart-home:access:execute  # только открытие
    - smart-home:events:read
  
  tenant_guest:
    - smart-home:access:execute  # в определенное время
    - smart-home:devices:read    # только свои устройства
  
  property_manager:
    - smart-home:*
    - smart-home:audit:read
```

#### **Модель ABAC (Attribute-Based Access Control)**
```json
{
  "policy": "Разрешить открытие двери если",
  "conditions": [
    {"user.role": "IN", "values": ["tenant_owner", "tenant_family"]},
    {"time.current": "BETWEEN", "values": ["06:00", "23:00"]},
    {"device.status": "==", "value": "online"},
    {"user.property_id": "==", "value": "device.property_id"}
  ]
}
```

#### **Контекстуальные ограничения**
1. **Временные ограничения**: Гостевой доступ только с 8:00 до 22:00
2. **Географические**: Управление только с российских IP
3. **Устройственные**: Только с доверенных устройств (мобильное приложение)

### **3.2. Специальные требования для биометрии**

#### **Обработка биометрических данных**
```
1. Локальная обработка: Распознавание лиц происходит на edge-устройствах
2. Минимизация передачи: В систему передается только факт распознавания + confidence score
3. Анонимизация: В логах биометрические данные заменяются на хэши
4. Согласие: Явное согласие пользователя на обработку биометрии
5. Хранение: Шаблоны лиц хранятся только на устройствах, не в облаке
```

#### **Распознавание номеров автомобилей**
```
1. Маскирование в логах: А123БC** (первые 6 символов)
2. Автоматическое удаление: Данные удаляются через 30 дней
3. Уведомления: Оповещение о неизвестных номерах
4. White-list: Приоритет для номеров из белого списка
```
